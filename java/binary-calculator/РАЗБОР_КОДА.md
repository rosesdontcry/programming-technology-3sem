# Подробный разбор калькулятора: от запуска до каждой функции

Здесь разобран исходный код калькулятора из коммита `fdbec99`. Позже к проекту добавлены этот документ и ссылка на него в README; сам Java-код при этом не изменялся. Другие лабораторные работы на Python из этого репозитория к калькулятору не относятся.

Наша цель — не просто перечислить методы, а пройти тот же путь, который проходит программа: от запуска окна до ввода числа, вычисления и отображения результата. После этого разберём сборку, стили и **обе группы тестов**. Все номера строк далее относятся к конкретному указанному файлу; если код изменится, номера могут сдвинуться.

**Как читать номера строк.** Запись `L32` значит «строка 32 указанного сейчас файла». Если одно выражение занимает две строки, они объясняются вместе. Пустые строки служат для отделения частей программы. Строка только с `{` начинает блок, а строка только с `}` завершает ближайший соответствующий блок; их смысл одинаков во всех методах, поэтому отдельно повторять это для каждой скобки не будем. Комментарий после `//` или между `/**` и `*/` предназначен человеку и не выполняется.

**Оглавление:** 0 — карта и термины; 1 — запуск окна; 2 — создание строк; 3 — кнопки; 4 — ввод, дроби и перевод систем; 5 — вычисления, степени и корни; 6 — Maven, CSS и служебные файлы; 7 — тесты логики; 8 — тесты интерфейса; 9 — краткий план защиты и указатель методов.

В корне всего репозитория также есть `.gitignore`. Он не является кодом калькулятора, но указывает Git, например, не добавлять результаты Maven-сборки. Папка `target/` создаётся при сборке: это **сгенерированные** классы и результаты тестов, а не ещё один исходный файл, который надо объяснять преподавателю.

### Главная цепочка вызовов

```text
main()
  → JavaFX launch(...)
  → start(stage)
  → buildScene()
      → три объекта NumberEntryRow и кнопки операций

Пользователь меняет текст
  → NumberEntryRow.filter() разрешает или отклоняет изменение
  → слушатель textProperty вызывает NumberEntryRow.update()
  → CalculatorLogic.parse(): текст → Fraction
  → CalculatorLogic.format(): Fraction → текст другого поля
  → NumberEntryRow.sync(): обновление другого поля без бесконечного цикла
  → onChange.run() → BinaryCalculator.recalculate()
  → CalculatorLogic.calculate(): выбор операции через switch
      → при необходимости power(), root(), exactRoot() и другие помощники
  → result.setValue(): перевод результата в два поля
```

**Важно:** до того как оба операнда введены, `recalculate()` оставляет результат пустым. При некорректной операции или превышении пределов происходит то же самое. Дополнительного сообщения об ошибке интерфейс не показывает.

### Несколько обозначений Java, которые постоянно встречаются

- `class` — описание типа объектов; объект создаётся через `new`.
- `extends` — наследование: класс получает возможности другого класса.
- `private` — доступ только внутри текущего класса. Отсутствие модификатора означает доступ внутри пакета `calculator`.
- `final` у поля означает, что после присваивания ссылку нельзя заменить; у класса — что от него нельзя наследоваться. `BigInteger` также неизменяем: его `add`, `multiply` и другие методы возвращают **новое** число.
- `static` означает, что поле или метод относятся к классу, а не к отдельному объекту.
- `void` — метод ничего не возвращает; `return` в таком методе может просто закончить его работу.
- `null` — отсутствие объекта. Например, `value == null` означает «сейчас в этой строке нет корректного числа».
- `if` — условие; `else` — другая ветвь; `while` и `for` — циклы; `switch` выбирает одну ветвь по значению.
- `try`/`catch` — попытка выполнить код и обработка исключения. `finally` выполняется при выходе из `try`, даже если возникла ошибка.
- `() -> ...` — лямбда, то есть передаваемое действие; `this::recalculate` — ссылка на конкретный метод текущего объекта. Их не запускают в момент передачи: запускают позже по событию.
- `a ? b : c` — условное выражение: если `a` истинно, результат `b`, иначе `c`.

# 1. Откуда программа стартует: `BinaryCalculator.java`

**Роль файла.** Это вход в приложение и связующее звено между тремя строками и операциями. Здесь нет алгоритмов перевода дробей: ими занимаются другие два класса.

## 1.1. Пакет, импорты и поля

- **L1 `package calculator;`** — класс принадлежит пакету `calculator`. Остальные три основных класса находятся там же, поэтому они могут обращаться друг к другу по именам без полных путей.
- **L3 `Application`** — базовый класс приложения JavaFX. Он отвечает за жизненный цикл графической программы.
- **L4 `Insets`** — отступы внутри контейнера.
- **L5 `Scene`** — сцена, то есть содержимое окна.
- **L6 `Separator`** — визуальный разделитель.
- **L7 `ToggleButton`** — кнопка с состоянием «выбрана/не выбрана».
- **L8 `ToggleGroup`** — группа, в которой выбирается одна кнопка операции.
- **L9 `Tooltip`** — подсказка при наведении.
- **L10–11 `HBox`, `VBox`** — контейнеры, которые располагают дочерние элементы по горизонтали и вертикали.
- **L12 `Stage`** — само окно JavaFX.
- **L14 `public class BinaryCalculator extends Application`** — объявление главного класса. `public` позволяет JavaFX запустить его; `extends Application` означает, что он является приложением JavaFX.
- **L15 `first`** — ссылка на строку первого операнда.
- **L16 `second`** — ссылка на строку второго операнда.
- **L17 `result`** — ссылка на строку результата.
- **L18 `operation = "+"`** — выбранная операция по умолчанию. Это строка, которую затем прочитает `CalculatorLogic.calculate`.

До вызова `buildScene` ссылки `first`, `second`, `result` ещё не содержат созданных строк. Они получат объекты на L32–34.

## 1.2. `main` — формальная точка входа

**Где:** L78–80. **Кто вызывает:** запуск Java. **Кого вызывает дальше:** инфраструктуру JavaFX через `launch`.

- **L78 `public static void main(String[] args)`** — стандартный метод запуска Java-программы. `args` — аргументы командной строки, а `static` позволяет запустить метод без заранее созданного объекта `BinaryCalculator`.
- **L79 `launch(args);`** — передаёт управление JavaFX и запускает жизненный цикл приложения. JavaFX подготавливает графическую среду, создаёт приложение и вызывает его метод `start(Stage)`. Не надо понимать это как обычное мгновенное рисование окна одной строкой: `launch` инициирует работу JavaFX.

## 1.3. `start` — создаём и показываем окно

**Где:** L20–29. **Связь:** JavaFX вызывает его после `launch`; метод обращается к `buildScene` и загружает CSS.

- **L20 `@Override`** — сообщает компилятору, что метод ниже переопределяет метод базового `Application`.
- **L21 `public void start(Stage stage)`** — JavaFX передаёт методу окно `stage`.
- **L22 `Scene scene = buildScene();`** — строим содержимое окна. Здесь сразу переходим к описанному ниже `buildScene()`.
- **L23 `scene.getStylesheets().add(getClass().getResource("/dark-theme.css").toExternalForm());`** — находим ресурс `dark-theme.css` в ресурсах приложения, превращаем адрес ресурса в строку URL и добавляем его в список стилей сцены. Само вычисление чисел CSS не меняет.
- **L24 `stage.setScene(scene);`** — помещаем подготовленную сцену в окно.
- **L25 `stage.setTitle("Калькулятор");`** — задаём заголовок окна.
- **L26 `stage.setMinWidth(550);`** — запрещаем уменьшать окно уже 550 единиц интерфейса JavaFX.
- **L27 `stage.setMinHeight(350);`** — аналогично задаём минимальную высоту.
- **L28 `stage.show();`** — показываем окно. Пока этот вызов не выполнен, созданная сцена ещё не показана пользователю как обычное окно.

## 1.4. `buildScene` — что именно окажется в окне

**Где:** L31–38. **Вызывается из:** `start`; в тестах его вызывают напрямую, чтобы получить дерево элементов.

- **L31 `Scene buildScene()`** — метод возвращает готовую сцену. Отсутствие `public`/`private` оставляет доступ внутри пакета, в том числе тестам из `calculator`.
- **L32 `first = new NumberEntryRow("Первое число", true, this::recalculate);`** — создаём первую строку. Текст — её заголовок; `true` разрешает редактирование; ссылка `this::recalculate` означает: «когда значение строки изменится, вызови `recalculate` этого окна». Сейчас метод не вызывается, а передаётся как действие на будущее.
- **L33** — таким же образом создаём редактируемую строку второго числа с той же обратной связью на `recalculate`.
- **L34 `result = new NumberEntryRow("Результат", false, () -> {});`** — создаём строку результата. `false` запрещает пользователю редактировать её текстовые поля. Пустая лямбда — действие, которое ничего не делает: изменение этой строки само по себе не должно инициировать ещё один пересчёт.
- **L35 `new VBox(10, first, operationButtons(), second, new Separator(), result)`** — создаём вертикальный контейнер с расстоянием 10 между элементами. Сверху вниз идут первое число, горизонтальная строка кнопок, второе число, разделитель и результат. В процессе вычисления аргументов вызывается `operationButtons()`.
- **L36 `root.setPadding(new Insets(16));`** — внутренний отступ от краёв контейнера равен 16.
- **L37 `return new Scene(root, 680, 380);`** — возвращаем сцену с корневым контейнером и начальными размерами 680 × 380.

В этот момент конструктор `NumberEntryRow` уже создал поля и подписки. Сначала разберём его — иначе дальнейшая реакция на ввод будет непонятна.

# 2. Как создаётся одна строка: `NumberEntryRow.java`

## 2.1. Пакет, импорты, поля

- **L1** — тот же пакет `calculator`.
- **L3 `Insets`** — отступы; **L4 `ComboBox`** — выпадающий список; **L5 `Label`** — подпись; **L6 `TextField`** — текстовое поле; **L7 `TextFormatter`** — фильтр изменений текста.
- **L8 `HBox`** — горизонтальный контейнер; **L9 `Priority`** — приоритет расширения; **L10 `VBox`** — вертикальный контейнер.
- **L12 `final class NumberEntryRow extends VBox`** — каждая строка сама является вертикальным контейнером. Класс не наследуют дальше; пакетный доступ достаточен для остальных классов калькулятора.
- **L13 `binary = new TextField()`** — левое поле двоичной записи. Ссылка `final`, но сам текст внутри поля может меняться.
- **L14 `converted = new TextField()`** — правое поле записи в выбранном основании.
- **L15 `base = new ComboBox<>()`** — отдельный для этой строки список оснований; `<Integer>` означает, что его значения — целые числа.
- **L16 `onChange`** — действие типа `Runnable`, которое нужно выполнить после изменения значения строки. Для двух операндов это ссылка на `recalculate`, для результата — пустая лямбда.
- **L17 `Fraction value`** — хранимое численное значение. Изначально `null`; оно важнее текста, потому что текст другого поля может быть округлён.
- **L18 `boolean syncing`** — защита от бесконечных взаимных обновлений. Для `boolean` значение по умолчанию — `false`.

## 2.2. Конструктор `NumberEntryRow`

**Где:** L20–49. **Вызывается из:** `buildScene()` три раза. Конструктор не возвращает объект через `return`: `new` создаёт объект, а конструктор его настраивает.

- **L20** — получает `title` — заголовок, `editable` — можно ли редактировать поля, и `onChange` — действие при изменении.
- **L21 `super(3);`** — вызывает конструктор родительского `VBox`, устанавливая расстояние 3 между его дочерними элементами.
- **L22 `this.onChange = onChange;`** — сохраняет переданное действие в поле именно этого объекта. `this.onChange` — поле, а просто `onChange` справа — параметр конструктора.
- **L23 `Label label = new Label(title);`** — создаёт подпись строки.
- **L24 `label.getStyleClass().add("section-label");`** — добавляет CSS-класс. Позже правило `.section-label` в `dark-theme.css` задаст оформление подписи.
- **L25 `configureField(binary, "Двоичное число", editable);`** — настраивает левое поле; переходим к следующему методу.
- **L26** — аналогично настраивает правое поле с другой подсказкой.
- **L27 `base.getItems().addAll(2, 8, 10, 16);`** — добавляет четыре допустимых основания именно в список этой строки.
- **L28 `base.setValue(10);`** — начальное основание правого поля — десятичное.
- **L29 `setAccessibleText(...)`** — задаёт описание списка для средств доступности, например экранного диктора; это не вводимое число.
- **L30 `HBox row = new HBox(6, binary, converted, base);`** — создаёт горизонтальный контейнер с расстоянием 6: левое поле, правое поле, список основания.
- **L31 `row.setPadding(new Insets(2));`** — добавляет внутренний отступ горизонтальной строке.
- **L32 `HBox.setHgrow(binary, Priority.ALWAYS);`** — разрешает левому полю получать дополнительное горизонтальное место, когда контейнер растёт.
- **L33** — аналогично для правого поля. Ограничения размеров полей задаются ещё и в CSS.
- **L34 `getChildren().addAll(label, row);`** — добавляет подпись и горизонтальную строку внутрь текущего `VBox`.
- **L36 `binary.setTextFormatter(filter(true));`** — создаёт фильтр для левого поля: аргумент `true` означает «это двоичное поле».
- **L37 `converted.setTextFormatter(filter(false));`** — фильтр для правого поля будет ориентироваться на выбранное основание.
- **L38–39** — подписывает слушатель на изменение текста левого поля. `obs` — изменяемое свойство, `oldText` и `newText` — старый и новый текст. Когда изменение действительно произошло, вызывается `update(oldText, newText, converted, 2, base.getValue())`: источник имеет основание 2, цель — правое поле с текущим основанием.
- **L40–41** — зеркальная подписка для правого поля: целью становится `binary`, основание источника берётся из `base`, а цели равно 2.
- **L42** — слушатель на изменение значения выпадающего списка.
- **L43–44** — если новое значение основания стало `null`, восстанавливаем прежнее, чтобы в строке не осталось «невыбранного» основания.
- **L45–46** — иначе вызываем `changeBase()`, который заново отображает уже имеющееся значение в правом поле.
- **L47–49** — закрывают ветку, лямбду слушателя и конструктор.

Заметьте разницу: **установка слушателя** происходит при создании окна, а тело слушателя начинает работать **потом**, когда пользователь меняет поле или основание.

## 2.3. `configureField` — общие настройки обоих полей

**Где:** L51–56. **Вызывается из:** конструктора дважды.

- **L51** — принимает конкретное поле `field`, текст подсказки `prompt` и флаг доступности редактирования.
- **L52 `field.getStyleClass().add("number-field");`** — добавляет CSS-класс полю. Поэтому CSS-правило `.number-field` применяется к обоим полям.
- **L53 `field.setPromptText(prompt);`** — задаёт серую подсказку, видимую в пустом поле; она не считается введённым текстом.
- **L54 `field.setAccessibleText(prompt);`** — задаёт описание для средств доступности.
- **L55 `field.setEditable(editable);`** — разрешает или запрещает **пользовательское** редактирование. Программа всё равно может устанавливать текст результата через `setText`.

## 2.4. `filter` — проверка изменения ещё до помещения текста в поле

**Где:** L58–79. **Связь:** созданный в конструкторе `TextFormatter` запускает переданную лямбду при попытке изменения текста. Если вернуть `null`, конкретное изменение отклоняется; если вернуть `change`, оно разрешается.

- **L58** — комментарий о правилах ввода: минус только в начале, допустимые цифры и не более одной точки.
- **L59 `filter(boolean binaryField)`** — параметр указывает, фильтруется ли левое двоичное поле.
- **L60 `return new TextFormatter<>(change -> {`** — создаёт и возвращает форматировщик с обработчиком изменения `change`. Тело лямбды будет выполняться при последующих правках.
- **L61 `String text = change.getControlNewText();`** — получаем полный текст, который был бы в поле **после** предлагаемого изменения.
- **L62 `int radix = binaryField ? 2 : base.getValue();`** — для левого поля основание 2, для правого — выбранное значение.
- **L63 `boolean tooLong = text.length() > CalculatorLogic.MAX_INPUT_DIGITS + 2;`** — проверяем общую длину против 2114: 2112 цифр плюс возможные знак и точка.
- **L64–65** — если текст длиннее, сохраняем первые `2112 + 3 = 2115` символов. Зачем на один больше допустимого? Чтобы после очень длинной вставки в поле осталось **заведомо недопустимое** значение: дальнейший `parse` его отвергнет, а старый результат не останется на экране как будто ввод принят.
- **L67 `String digits = "0123456789ABCDEF".substring(0, radix);`** — берём набор разрешённых цифр. При `radix = 2` это `01`, при 8 — `01234567`, при 10 — `0123456789`, при 16 — все символы до `F`.
- **L68** — собираем строку с регулярным выражением. Для двоичного поля выражение во время работы выглядит так: `(?i)-?[01]*(\.[01]*)?`. `(?i)` разрешает одинаково прописные и строчные буквы; `-?` — необязательный начальный минус; `[01]*` — ноль или больше допустимых цифр; `(\.[01]*)?` — необязательная точка и цифры после неё. В **исходном Java-коде** эта точка записана как `\\.`: двойной обратный слеш нужен строковому литералу, чтобы в само регулярное выражение попало `\.` — обозначение буквальной точки.
- **L69 `if (!text.matches(pattern))`** — `matches` проверяет, соответствует ли **весь** предложенный текст шаблону; `!` меняет ответ на противоположный.
- **L70 `return null;`** — если текст не подходит, отклоняем именно это изменение. Например, `2` не будет добавлена в двоичное поле.
- **L72–75** — если была обрезка длинного ввода, подменяем изменение: L73 задаёт заменяемым диапазоном всё старое содержимое, L74 устанавливает обрезанный текст, L75 ставит выделение/курсор в его конец.
- **L77 `return change;`** — разрешаем корректное или намеренно обрезанное изменение.
- **L78–79** — закрываются лямбда форматировщика и метод.

Шаблон специально разрешает промежуточные `""`, `"-"`, `"."`, `"-."`, чтобы человек мог начать ввод. Это ещё не числа: следующий `parse` их отвергает, поэтому связанное поле и результат временно пусты. Когда пользователь дописывает цифру, строка восстанавливается.

Переменная названа `ignored`, потому что содержимое исключения не выводится.
- **L96 `sync(target::clear);`** — очищаем второе поле, не позволяя его слушателю создать цикл. Исходное поле остаётся доступным для исправления.
- **L98 `onChange.run();`** — сообщаем владельцу строки об изменении. У операндов это приведёт к `BinaryCalculator.recalculate()`, у результата выполнится пустое действие.

### Почему нужно `keepsExactValue`, хотя отдельного индикатора нет?

Пусть пользователь ввёл в десятичном поле `0.8`. В `value` лежит ровно `4/5`. В двоичном поле это бесконечная дробь, поэтому показан ограниченный по длине текст. Если к этому тексту просто приписать ноль справа, **показанное двоичное число** не изменится. Было бы плохо вместо исходной точной `4/5` внезапно взять за новое значение её ограниченную запись. Поэтому программа сохраняет исходную дробь.

Это внутреннее правило сохранения данных, а не функция показа какого-либо знака. Если изменить значащую двоичную цифру, программа, напротив, должна принять новую запись как новое значение.

## 4.2. `CalculatorLogic.keepsExactValue`

**Где:** `CalculatorLogic.java`, L87–94. **Вызывается из:** `NumberEntryRow.update` до обычного разбора нового текста.

- **L87** — принимает хранимую дробь `value`, старый и новый тексты и их основание; возвращает `boolean`.
- **L88 `try`** — разбор любого из текстов может завершиться исключением.

## 4.4. `CalculatorLogic.parse` — текст в рациональную дробь

**Где:** `CalculatorLogic.java`, L16–40. **Вызывается из:** `update`, `keepsExactValue`, `fromDouble`, а также тестов. Возвращает `Fraction`.

Идея: убрать точку и поделить полученное целое число на основание в степени количества цифр после точки. Например, двоичное `101.01₂`: убрали точку — `10101₂ = 21`; после точки было 2 цифры, знаменатель `2² = 4`; получается `21/4 = 5.25`.

- **L16** — комментарий с этим примером; индекс `₂` означает двоичную запись.
- **L17 `static Fraction parse(String text, int base)`** — принимает строку и основание, возвращает дробь.
- **L18 `checkBase(base);`** — сначала убеждаемся, что основание допустимо. Этот помощник будет разобран сразу после `parse`.
- **L19 `if (text == null || text.isEmpty())`** — проверка отсутствующей или пустой строки. `||` означает «или»; если `text == null`, Java не вызывает `isEmpty()` у `null`.
- **L20 `throw new NumberFormatException("Empty input");`** — сообщаем вызывающему коду исключением, что числа нет. Это не означает, что пользователь увидит сообщение: `update` его ловит.
- **L22–23** — если общая длина больше 2114 символов, сразу прекращаем разбор, не пытаясь строить очень большие числа.
- **L25 `int point = text.indexOf('.');`** — индекс первой точки; если точки нет, `indexOf` возвращает `-1`.
- **L26** — проверка формы записи: первая и последняя точки должны совпадать, знак `+` не разрешён, а `-` не должен **первый раз** встретиться после нулевой позиции. Если в строке окажется дополнительный минус, которого эта проверка не выявила, его позже отклонит `new BigInteger(...)`.
- **L27** — при нарушении формы выбрасывается `NumberFormatException`.
- **L29 `text.replace(".", "")`** — получаем новую строку без точки. Исходная строка при этом не меняется.
- **L30** — считаем цифры как длину строки без точки, вычитая один символ, если в начале стоит `-`.
- **L31–32** — если цифр больше 2112, прекращаем разбор. Эта проверка нужна отдельно от общей длины: например, 2113 нулей без знака и точки ещё укладываются в 2114 символов, но уже превышают предел по цифрам.
- **L34–35** — если цифр вообще нет, отклоняем промежуточные `-`, `.` и подобные записи.
- **L37 `places = point < 0 ? 0 : text.length() - point - 1;`** — количество цифр после точки: без точки оно равно нулю.
- **L38 `new BigInteger(digits, base)`** — разбираем строку без точки в заданном основании. Конструктор также проверяет, допустимы ли её цифры, и создаёт большое целое число.
- **L39 `new Fraction(numerator, BigInteger.valueOf(base).pow(places))`** — знаменатель равен `base^places`. Создаём дробь; в её конструкторе выполняются сокращение и проверка предела.

## 4.6. Как `parse` создаёт число: `Fraction.java`

**Роль файла:** одна неизменяемая обыкновенная дробь. Это не графический элемент и не текст для экрана. Два поля `Fraction` — числитель и знаменатель — представляют **одно** число.

### Заголовок и поля

- **L1** — пакет `calculator`.
- **L3 `import java.math.BigInteger;`** — используем целые числа произвольной длины.
- **L5** — комментарий: число представлено как числитель, делённый на знаменатель.
- **L6 `final class Fraction`** — класс не предназначен для наследования.
- **L7 `LIMIT = BigInteger.ONE.shiftLeft(53)`** — единица, сдвинутая влево на 53 бита: это `2^53 = 9007199254740992`.
- **L8 `final BigInteger numerator`** — числитель.
- **L9 `final BigInteger denominator`** — знаменатель. Поля присваиваются один раз при создании объекта; `BigInteger` тоже неизменяем.

### Конструктор `Fraction`

**Где:** L11–26. **Вызывается из:** `parse`, арифметических операций, `power`, `root`, `integer` и тестов. Все пути создания дроби поэтому проходят одинаковую нормализацию и проверку диапазона.

- **L11** — получает потенциальные числитель и знаменатель. Параметры конструктора пока не обязательно приведены к удобному виду.
- **L12 `if (denominator.signum() == 0)`** — `signum()` возвращает `-1`, `0` или `1` в зависимости от знака числа; проверяется нулевой знаменатель.
- **L13 `throw new ArithmeticException("Division by zero");`** — дробь со знаменателем ноль создать нельзя. Интерфейс позже поймает исключение и оставит результат пустым.
- **L15** — если знаменатель отрицательный, удобнее перенести знак наверх.
- **L16 `numerator = numerator.negate();`** — меняем знак числителя.
- **L17 `denominator = denominator.negate();`** — меняем знак знаменателя. Значение дроби при этом не меняется: `10/(-20) = -10/20`.
- **L19** — комментарий объясняет сокращение.
- **L20 `BigInteger divisor = numerator.gcd(denominator);`** — находим наибольший общий делитель. `gcd` возвращает неотрицательное значение, в том числе для отрицательного числителя.
- **L21 `this.numerator = numerator.divide(divisor);`** — сокращённый числитель сохраняется в поле объекта.
- **L22 `this.denominator = denominator.divide(divisor);`** — сокращённый знаменатель сохраняется в поле. Например, `8/10` превращается в `4/5`; ноль приводится к `0/1`.
- **L23 `abs(numerator).compareTo(denominator * LIMIT) > 0`** — сравниваем модуль дроби с `2^53` без неточного вещественного деления: `|n|/d > LIMIT` равносильно `|n| > d * LIMIT`, поскольку знаменатель уже положителен.
- **L24** — если предел превышен, выбрасываем `ArithmeticException`. Сам конструктор не рисует ошибку.

### `Fraction.isInteger`

**Где:** L28–30. **Используется:** при степенях и корнях.

- **L28** — метод возвращает `boolean`.
- **L29 `return denominator.equals(BigInteger.ONE);`** — после сокращения дробь является целой ровно тогда, когда знаменатель равен 1. Для сравнения объектов `BigInteger` используется `.equals`, а не `==`.

### `Fraction.sameValue`

**Где:** L32–34. **Используется:** в `keepsExactValue`.

- **L32** — принимает вторую дробь `other`.
- **L33** — возвращает `true`, если равны и числители, и знаменатели. Это работает именно потому, что конструктор всегда приводит знак и сокращает дроби: например, и `8/10`, и `4/5` хранятся как `4/5`.

Теперь `parse` может вернуть в `update` готовую дробь. Следующий вызов в `update` — `format`, чтобы записать то же значение во второе поле.

## 4.7. `CalculatorLogic.format` — дробь обратно в текст нужной системы

**Где:** `CalculatorLogic.java`, L42–73. **Вызывается из:** `update`, `changeBase`, `setValue` и тестов. Принимает точную `Fraction` и основание; возвращает строку для поля.

Идея деления по шагам: сначала находим целую часть и остаток. Затем умножаем остаток на основание новой системы; целая часть деления на знаменатель даёт очередную цифру после точки, новый остаток идёт на следующий шаг.

Например, `21/4` в двоичной системе: целая часть `5 = 101₂`, остаток `1`; `1·2/4` даёт цифру `0` и остаток `2`; `2·2/4` даёт цифру `1` и остаток `0`. Ответ `101.01₂`.

## 5.1. `BinaryCalculator.recalculate`

- **L72 `result.setValue(CalculatorLogic.calculate(...))`** — сначала Java вычисляет аргументы: берёт обе дроби через `getValue`, передаёт их и `operation` в `calculate`; затем передаёт возвращённую дробь в `result.setValue`, который формирует два текста.
- **L73 `catch (IllegalArgumentException | ArithmeticException ignored)`** — обрабатываем неправильную операцию, деление на ноль, выход за предел или невозможность отображения.

## 5.2. `CalculatorLogic.calculate` — выбор действия через `switch`

**Где:** `CalculatorLogic.java`, L96–110. **Вызывается из:** `recalculate` и тестов.

Обозначим `a = aₙ/a𝒹`, `b = bₙ/b𝒹`. Тогда для общего знаменателя можно взять `a𝒹·b𝒹`.

- **L96** — принимает два объекта `Fraction` и строку операции.
- **L97 `left = a.numerator.multiply(b.denominator)`** — левая доля общего числителя: `aₙ·b𝒹`.
- **L98 `right = b.numerator.multiply(a.denominator)`** — правая доля общего числителя: `bₙ·a𝒹`.
- **L99 `commonDenominator = a.denominator.multiply(b.denominator)`** — общий знаменатель `a𝒹·b𝒹`.
- **L100 `return switch (operation)`** — Java 17 выбирает ветвь по строке и возвращает результат этой ветви.
- **L101 `case "+"`** — сумма: `(left + right)/commonDenominator`; создаётся и нормализуется новая `Fraction`.
- **L102 `case "−"`** — разность: `(left - right)/commonDenominator`.
- **L103 `case "×"`** — произведение: `(aₙ·bₙ)/(a𝒹·b𝒹)`.
- **L104 `case "÷"`** — частное: `(aₙ·b𝒹)/(bₙ·a𝒹)`, то есть `left/right`. Если второй операнд нулевой, знаменатель станет нулём и конструктор `Fraction` выбросит исключение.
- **L105 `case "mod"`** — остаток как `(left.remainder(right))/commonDenominator`. `BigInteger.remainder` имеет знак делимого, поэтому, например, `-5 mod 3 = -2`. При нулевом делителе возникает исключение.
- **L106 `case "^" -> power(a, b);`** — делегируем возведение в степень методу `power`.
- **L107 `case "√" -> root(a, b);`** — делегируем корень; `a` — степень корня, `b` — подкоренное число.
- **L108 `default -> throw ...`** — неизвестный символ операции не должен молча трактоваться как другая операция.
- **L109** — точка с запятой завершает выражение `switch`, возвращаемое методом.

### Пример `0.8 − 0.7` по этим строкам

1. `parse("0.8", 10)` создаёт `8/10`, конструктор сокращает до `4/5`.
2. `parse("0.7", 10)` создаёт `7/10`.
3. Выбрана кнопка `−`, поэтому `operation = "−"`.
4. `left = 4·10 = 40`, `right = 7·5 = 35`, общий знаменатель `5·10 = 50`.
5. Ветка вычитания создаёт `5/50`; конструктор сокращает её до `1/10`.
6. `result.setValue` вызывает `format` для основания 2 и отдельно для основания результата. В десятичной системе показывается `0.1`; двоичная запись ограничивается доступной точностью. Ошибка двоичного `double` здесь не участвует.

Теперь рассмотрим особые ветви `power` и `root`.

## 5.3. `CalculatorLogic.power` — возведение в степень

**Где:** `CalculatorLogic.java`, L112–145. **Вызывается из:** `calculate` для `^` и из одной специальной ветви `root`. Параметры — дробь `base` и дробь `exponent`.

- **L117–118** — отрицательный показатель у нулевого основания потребовал бы деления на ноль, поэтому выбрасывается исключение.

- **L134 `int n = magnitude.intValue();`** — после проверки безопасно получаем показатель для `BigInteger.pow(int)`.
- **L135–137** — оцениваем размер будущих числителя и знаменателя: количество бит исходного числа умножается на `n`. Если оценка превышает 65536, останавливаемся, чтобы не создавать слишком тяжёлые промежуточные значения. Это защитная оценка сверху, а не обещание, что фактический размер всегда равен произведению.
- **L139 `base.numerator.pow(n)`** — точно возводим числитель в неотрицательную степень `n`.
- **L140 `base.denominator.pow(n)`** — точно возводим знаменатель в `n`.
- **L141–142** — если исходный показатель отрицательный, меняем числитель и знаменатель местами; иначе оставляем порядок. Конструктор сокращает результат и проверяет его величину. Например, `2^-3 = 1/8`.
- **L144 `fromDouble(Math.pow(toDouble(base), toDouble(exponent)))`** — если показатель не целый и ранее не сработала специальная ветка, переводим аргументы в `double`, используем `Math.pow`, затем переводим полученное конечное значение обратно в `Fraction`. Это **приближённый** путь, а не точная рациональная арифметика.

- **L153–154** — отрицательное подкоренное число разрешено только для **целой нечётной** степени. `!degree.isInteger()` проверяет нецелую степень, а `!degree.numerator.abs().testBit(0)` — чётную целую. Например, `³√(-8)` допустим, `²√(-8)` — нет.
- **L156** — специальная ветвь нулевого подкоренного числа.
- **L157–158** — если степень корня отрицательная, результат требовал бы деления на ноль, поэтому исключение.
- **L160** — при положительной степени возвращаем ноль.
- **L162** — проверка подкоренного числа `1` или `-1` по модулю.
- **L163** — возвращаем `1` или `-1`; допустимость отрицательного случая уже проверена на L153.
- **L165** — отдельный точный случай: подкоренное число неотрицательно, степень не целая и числитель сокращённой степени по модулю равен 1. Тогда обратная ей степень будет целой.
- **L166** — вычисляет этот целый показатель: если степень корня отрицательная — отрицательный знаменатель, иначе положительный знаменатель. Например, степень корня `1/2` даёт показатель `2`.
- **L167 `return power(number, integer(exponent));`** — передаёт задачу уже разобранному `power`: например, корень степени `0.5` из `9` равен `9^2 = 81`.
- **L169** — пробуем точный корень, если степень целая и её модуль не больше 16384. Здесь речь об ограничении числа, передаваемого в поиск точного корня.
- **L170** — получаем модуль степени как `int`.
- **L171** — ищем точный целый корень нужной степени из модуля числителя.
- **L172** — отдельно ищем точный целый корень из знаменателя.
- **L173** — если оба корня найдены, дробь имеет точный рациональный корень.
- **L174–175** — для разрешённого отрицательного подкоренного числа возвращаем минус числителю.
- **L177–178** — если исходная степень корня отрицательная, обращаем полученную дробь; иначе возвращаем её как есть. Например, корень степени `-3` из `-8` равен `-1/2`.
- **L181 `Math.pow(Math.abs(toDouble(number)), 1.0 / toDouble(degree))`** — если точную ветвь применить не удалось, используем формулу `n-й корень x = |x|^(1/n)` с `double`. Для отрицательного подкоренного числа знак был проверен и временно убирается.
- **L182 `fromDouble(negative ? -result : result)`** — возвращаем отрицательный знак, если он нужен, и переводим полученное приближённое число в `Fraction`.

Следующий вопрос: как L171–172 определяют, существует ли **точный целый** корень?

## 5.5. `CalculatorLogic.exactRoot` — поиск точного целого корня

**Где:** `CalculatorLogic.java`, L185–213. **Вызывается из:** `root`. Возвращает целый корень или `null`, если точного целого корня нет. `value` здесь неотрицательно, `degree` положительно.

- **L185** — комментарий сообщает основной способ: двоичный поиск.
- **L186** — принимает `BigInteger value` и целую степень.
- **L187–188** — для степени 1 или числа 0/1 ответ известен сразу: возвращается само `value`.
- **L190–191** — если степень больше числа бит положительного `value`, при корне не меньше 2 такая степень уже была бы слишком большой; точного целого корня здесь нет, возвращаем `null`.
- **L193** — отдельно рассматривается квадратный корень.
- **L194 `BigInteger root = value.sqrt();`** — `BigInteger.sqrt()` находит целую часть квадратного корня.
- **L195** — проверяем `root * root == value`. Возвращаем корень только при точном совпадении; иначе `null`.
- **L197 `rootBits = (value.bitLength() + degree - 1) / degree`** — целочисленная формула округления вверх: `ceil(bitLength / degree)`. Она помогает получить безопасную верхнюю границу поиска.
- **L198 `low = BigInteger.ONE;`** — нижняя граница кандидатов.
- **L199 `high = BigInteger.ONE.shiftLeft(rootBits);`** — верхняя граница `2^rootBits`.
- **L200 `while (low.compareTo(high) <= 0)`** — пока диапазон кандидатов не пуст, продолжаем поиск.
- **L201 `middle = low.add(high).shiftRight(1)`** — середина диапазона: сумма границ, делённая на 2 целочисленным сдвигом.
- **L202 `middle.pow(degree).compareTo(value)`** — сравниваем степень кандидата с исходным числом: отрицательный результат — меньше, ноль — равно, положительный — больше.
- **L203–204** — при точном равенстве возвращаем `middle`.
- **L206–207** — если степень кандидата слишком мала, исключаем его и всё слева: `low = middle + 1`.
- **L208–209** — иначе степень слишком велика, исключаем кандидата и всё справа: `high = middle - 1`.
- **L212 `return null;`** — диапазон исчерпан, целого корня нет.

Пример `³√64`: `value = 64`, степень 3. Среди кандидатов находится 4, поскольку `4³ = 64`; после аналогичной проверки знаменателя 1 метод `root` получает точную дробь `4/1`.

## 5.6. `CalculatorLogic.integer` — удобное создание целого числа

**Где:** `CalculatorLogic.java`, L215–217. Вызывается из специальных ветвей `power` и `root`.

- **L215** — принимает `BigInteger number`, возвращает `Fraction`.
- **L216 `return new Fraction(number, BigInteger.ONE);`** — целое число `n` представляется дробью `n/1`. Конструктор всё равно проверяет общий предел.

## 5.7. `CalculatorLogic.toDouble` и `fromDouble` — только для приближённой ветви

Обычные ввод, перевод систем и арифметика `+`, `−`, `×`, `÷`, `mod` работают с `BigInteger` и `Fraction`. Переход к `double` нужен для той части степеней и корней, которую код передаёт `Math.pow`.

### `toDouble` — L225–233

- **L225** — комментарий поясняет назначение.
- **L226** — принимает дробь, возвращает `double`.
- **L227 `new BigDecimal(number.numerator)`** — переводит числитель в десятичное большое число для деления.
- **L228 `.divide(new BigDecimal(number.denominator), MathContext.DECIMAL128).doubleValue()`** — делит на знаменатель с контекстом `DECIMAL128` (34 значащие десятичные цифры), затем получает значение типа `double`. Последнее преобразование уже имеет ограниченную двоичную точность.
- **L229** — отклоняем не конечное `double` или ситуацию, когда ненулевая дробь при переводе стала `0.0` из-за слишком малого масштаба.
- **L230** — создаём `ArithmeticException`, чтобы программа не выдала ноль/бесконечность вместо недоступного корректного результата.
- **L232 `return value;`** — возвращаем пригодное значение.

### `fromDouble` — L235–240

- **L235** — принимает результат `Math.pow`, возвращает дробь.
- **L236 `if (!Double.isFinite(value) || value == 0.0)`** — отклоняет `NaN`, бесконечности и ноль, который в этой ветви может означать потерю слишком маленького ненулевого результата. Настоящие нулевые специальные случаи обработаны раньше в `power`/`root`.
- **L237** — сообщает вызывающему коду исключением, что результат недоступен.
- **L239 `parse(BigDecimal.valueOf(value).toPlainString(), 10)`** — преобразует конечный `double` в обычную десятичную строку без экспоненциальной формы и снова использует уже объяснённый `parse`. Возвращённая дробь точно хранит **эту десятичную запись приближённого значения**, но это не делает, например, иррациональный корень математически точным.

## 5.8. Полная цепочка ещё раз, теперь с именами

```text
Ввод "0.8" в правое поле первого операнда
  → filter(false): цифры разрешены для основания 10
  → слушатель converted.textProperty()
  → update(..., sourceBase = 10, targetBase = 2)
  → parse("0.8", 10)
  → new Fraction(8, 10) → сокращение до 4/5
  → format(4/5, 2) → двоичный текст
  → sync(() -> binary.setText(...))
  → value = 4/5
  → onChange.run() → recalculate()

Если второй операнд ещё пуст → result.clear() и return.
Если второй операнд уже введён → calculate(first, second, operation)
  → выбранная ветвь switch
  → при необходимости power/root/exactRoot
  → result.setValue(полученная Fraction)
  → format для 2 и для выбранного основания результата
  → sync записывает оба поля результата.
```

Если пользователь меняет только основание строки, путь короче: слушатель списка → `changeBase()` → `format` **уже хранимой** дроби → `sync` обновляет правое поле. Число не пересчитывается из округлённой записи.

## 8.5. `onFxThread` — L321–325: как тест выполняет действия с окнами

Эту вспомогательную функцию удобнее понять **до** сценариев: практически каждый тест передаёт ей лямбду.

- **L321 `private static <T> T onFxThread(Callable<T> action) throws Exception`** — принимает действие, возвращающее значение типа `T`; сам метод вернёт тот же результат или сообщит ошибку. В большинстве тестов результат не нужен, поэтому лямбда возвращает `null`.
- **L322 `FutureTask<T> task = new FutureTask<>(action);`** — оборачивает действие в задачу, завершения которой можно ждать.
- **L323 `Platform.runLater(task);`** — ставит задачу в очередь потока JavaFX. Обычный тестовый поток не должен напрямую выполнять эти UI-действия.
- **L324 `return task.get(10, TimeUnit.SECONDS);`** — ждёт результат не более 10 секунд. Если проверка внутри задачи упала или задача не завершилась, тест увидит исключение.

В каждом сценарии ниже `onFxThread(() -> { ... return null; });` означает: выполнить перечисленные действия и проверки на JavaFX-потоке, затем сообщить о завершении. `return null` не означает, что калькулятор возвращает ноль: это просто значение, требуемое интерфейсом `Callable` для тестового действия.

# 9. Как связно рассказать программу преподавателю

## 9.1. Короткий рассказ в правильном порядке

Можно объяснять проект примерно так, последовательно раскрывая детали, если преподаватель попросит:

1. **«Это приложение JavaFX. `main` вызывает `launch`, JavaFX вызывает `start`, а `start` строит и показывает сцену».** `BinaryCalculator` создаёт две строки операндов, строку результата и группу кнопок.
2. **«Каждая строка — отдельный `NumberEntryRow`».** У неё есть двоичное поле, поле другой системы, собственный список основания и точное хранимое значение `Fraction`. Поэтому основания всех трёх строк независимы.
3. **«Когда пользователь меняет текст, сначала работает фильтр, затем слушатель».** Фильтр проверяет символы, слушатель вызывает `update`, а `update` вызывает `parse` и `format`, чтобы обновить связанное поле.
4. **«Синхронизацию защищает `syncing`».** Программное изменение второго поля тоже вызывает его слушатель, но тот видит флаг и не запускает обратное обновление. `finally` восстанавливает флаг.
5. **«Числа хранятся рациональными дробями».** Например, введённые `0.8` и `0.7` становятся `4/5` и `7/10`, поэтому вычитание даёт точное `1/10`. `Fraction` сокращает дробь и запрещает нулевой знаменатель или результат за пределом.
6. **«После изменения операнда запускается `recalculate`».** Он очищает старый результат, проверяет оба числа и передаёт их с выбранным символом в `CalculatorLogic.calculate`.
7. **«В `calculate` операция выбирается через `switch`».** Обычная арифметика работает с целыми числителями и знаменателями; степени и корни передаются отдельным методам.
8. **«Точные целые степени и точные корни программа ищет отдельно».** Для корней она проверяет целые корни числителя и знаменателя; в остальных предусмотренных случаях использует `Math.pow`, поэтому там результат может быть приближённым.
9. **«Даже точную дробь не всегда можно конечным текстом записать в другой системе».** `format` получает дробные цифры по остаткам и при необходимости округляет отображение без отдельного знака. При некорректной операции или превышении ограничения результат остаётся пустым.
10. **«Maven собирает проект, CSS оформляет окно, JUnit проверяет вычисления и интерфейс».** Тесты не участвуют в обычной работе калькулятора.

## 9.2. Частые вопросы и честные ответы

**Почему не просто `double` для всего?**

Потому что многие десятичные дроби не представляются точно конечной двоичной дробью. `Fraction` хранит рациональные числа как два целых и позволяет точно выполнить основные действия. `double` всё равно используется в ветви `Math.pow` для части корней и дробных степеней.

**Дробь всегда выводится полностью?**

Нет. Внутреннее рациональное значение может быть точным, а его запись в выбранной системе — бесконечной. Программа ограничивает количество цифр и округляет текст. Для слишком маленького ненулевого значения, которое невозможно корректно показать в установленных пределах, результат остаётся пустым.

**Зачем `BigInteger`, если результат ограничен `2^53`?**

Даже при небольшом окончательном числе числитель, знаменатель и промежуточные произведения могут быть большими. `BigInteger` позволяет не терять их из-за переполнения обычного целого типа; отдельная проверка ограничивает именно допустимое значение.

**Что делает `gcd`?**

Находит наибольший общий делитель. Деление числителя и знаменателя на него сокращает дробь: `8/10 → 4/5`. Это уменьшает промежуточные значения и упрощает сравнение дробей.

**Как получается следующая цифра после точки?**

Остаток умножается на новое основание, после чего делится на знаменатель. Частное — очередная цифра, остаток используется дальше. Этот процесс находится в цикле `format`.

**Почему при пустом или ошибочном вводе не остаётся старый результат?**

`update` при неудаче сбрасывает значение строки и сообщает окну об изменении. `recalculate` в самом начале очищает результат и только потом пытается считать заново.

**Почему можно ввести только `-` или `.`?**

Это допустимые **промежуточные** состояния при наборе текста, а не готовые числа. Фильтр допускает такие строки, но `parse` их не считает числом; после добавления цифры строка восстанавливается.

**Зачем ограничивать длину ввода и вычисление степени?**

Чтобы не создавать необоснованно огромные значения и не перегружать приложение. При этом используются конкретные, описанные в README пределы; случай `0`, `1`, `-1` в степенях обрабатывается отдельно.

**Почему корень из `-8` третьей степени допустим, а второй — нет?**

В вещественных числах нечётная степень сохраняет отрицательный знак: `(-2)^3 = -8`. Чётная степень вещественного числа отрицательной быть не может. Код специально проверяет целую нечётную степень для отрицательного подкоренного числа.

**Что такое `mod` здесь?**

Остаток с усечением частного к нулю, как у `%` в Java; знак остатка следует первому числу. Например, `-5 mod 3 = -2`.

**Почему `0^0` равно 1?**

Это выбранное поведение конкретного калькулятора, закреплённое в первой ветви `power` и в тестах. В разных математических контекстах такой случай обсуждается отдельно; здесь важно говорить именно о принятом в программе правиле.

**Что доказывают тесты?**

Они проверяют перечисленные сценарии и ограничения, но конечный набор тестов не является математическим доказательством отсутствия всех ошибок. В текущей проверке прошли 28 тестов с headless JavaFX, из них 11 проверяют интерфейс; без дисплея и без Monocle эти 11 UI-тестов пропускаются.
